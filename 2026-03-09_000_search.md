### Acceptance Criteria

- [ ] Single-character searches return results (currently shows 0 results for "a")
- [ ] Search results page matches ServiceNow reference UI styling:
  - Hover background: `rgba(0, 128, 163, 0.1)`
  - Bottom border separators: `rgb(207, 213, 215)`
- [ ] Each category section renders its own metadata columns per the screenshots:
  - **Incidents:** Number, Opened, Caller, Priority, State, Category, Assignment group
  - **Change Requests:** Number, Type, Assignment group, State, Risk, Priority
  - **Groups:** Type (with description body text)
  - **Knowledge:** Category, Number, Updated
  - **Catalog Items:** Category, Price
- [ ] Category header shows count format: "Section Name (N of N)" with info icon (ⓘ) where applicable
- [ ] "Go to list view" link navigates to corresponding table page with search query filter in URL params (only for tables that exist)
- [ ] Clicking a result opens its detail page (e.g., `/knowledge/[id]` for knowledge articles)
- [ ] Result card has external link icon that opens item in new tab
- [ ] People - Groups category is included in search (currently missing)
- [ ] Search scope dropdown (Global, CSM/FSM, Service Ops, Knowledge Center) filters results when non-Global is selected

### Constraints

- Client-side only (static JSON data, no backend API)
- Only hook up "Go to list view" for tables that already have routes: `/knowledge`, `/contacts`. Incidents, Change Requests, Problems, Groups, and Catalog Items do NOT have dedicated routes yet.
- The app uses Next.js App Router with `src/app/` directory structure
- Search results page is at `/search?q=<query>`
- Existing implementation is in `src/app/search/page.tsx` on branch `feat/global-search`

### Risks

1. **Groups data missing** — There is no `groups.json` in `src/page-contents/`. Contacts data exists but Groups do not. Need to create mock groups data or skip this category.
2. **Detail page routing** — Only `/knowledge/[id]` exists for item detail views. Clicking an incident or change request result has nowhere to navigate. Need to decide: skip navigation for missing detail routes, or route to a generic detail page / coming-soon page.
3. **"Go to list view" URL params** — The ServiceNow URL pattern uses `GOTO123TEXTQUERY321=<query>` as a special search param. Our app does not have equivalent table views for most categories. Only knowledge has a full table page.
4. **Search scope dropdown** — Already rendered in `SearchWithScopeDropdown.tsx` but does nothing. Implementing scope filtering requires defining what each scope includes.
5. **Metadata layout mismatch** — Current implementation renders all metadata as a horizontal `<dl>` flex wrap. The reference screenshots show a more table-like horizontal layout with consistent column alignment across results in a section. This may need a different rendering approach per category.
