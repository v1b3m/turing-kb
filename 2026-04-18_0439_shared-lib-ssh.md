# Shared Lib Submodule via SSH

The `shared-libs` submodule is defined in `.gitmodules`. If that file points to an HTTPS GitHub URL, `git submodule sync` will copy the HTTPS URL back into local Git config and `git submodule update --init --recursive` will prompt for HTTPS credentials.

To force the submodule to use SSH with the `turing_github` host alias, update `.gitmodules`, sync, clear any partial clone state, then re-init:

```bash
git config --file .gitmodules submodule.shared-libs.url git@turing_github:TuringGpt/turing-gym-template-aws.git
git submodule sync -- shared-libs
rm -rf shared-libs .git/modules/shared-libs
git submodule update --init --recursive
```

Why this works:
- `git config --file .gitmodules ...` changes the source URL that `git submodule sync` copies from.
- `git submodule sync` updates the repo's live submodule config to match `.gitmodules`.
- Removing `shared-libs` and `.git/modules/shared-libs` clears the failed HTTPS clone state.
- The final `git submodule update --init --recursive` clones with SSH instead of HTTPS.

Quick verification:

```bash
git config --file .gitmodules --get submodule.shared-libs.url
git config --get submodule.shared-libs.url
```

Both should print:

```bash
git@turing_github:TuringGpt/turing-gym-template-aws.git
```
