## What was done
Wired the "Show" submenu in the hamburger menu to control how many rows are displayed per page. The submenu now reads/writes `rowsPerPage` from the Zustand store, and the table paginates accordingly with working first/prev/next/last navigation controls.

## Files touched

- `src/components/knowledge/KnowledgeArticlesTable.tsx` (modified) — Added `currentPage` state, pagination slicing for rows and groups, wired all four pagination buttons + page input

## Decisions made
- **rowsPerPage default is 20** — matches the previously hardcoded "checked" item in the static menu
- **currentPage is local state** — resets on rowsPerPage, searchQuery, sortCol, sortDir, groupByField, or activeViewId changes (no stale pages)
- **Group-by pagination paginates groups** — consistent with existing behavior that counted groups in the pagination bar
- **Select-all selects only current page rows** — standard table behavior
- **Store state (`rowsPerPage`, `setRowsPerPage`) was added by concurrent agent** — task 005 agent committed the store changes; no conflict

## Known limitations
- The page input accepts only valid page numbers (rejects invalid input silently) — no visual feedback for out-of-range
- With all 16 rows and default 20 per page, pagination is a no-op until row count exceeds 20

## How to verify
1. Navigate to `/knowledge`
2. Open hamburger menu → Show → select "10 rows per page"
3. Verify only 10 rows visible, pagination shows "1 to 10 of 16"
4. Click next page arrow → shows remaining 6 rows, "11 to 16 of 16"
5. Select "50 rows per page" → all 16 rows visible, pagination "1 to 16 of 16"
6. Enable Group By → verify pagination applies to groups
7. Verify Show submenu checkbox reflects current selection
