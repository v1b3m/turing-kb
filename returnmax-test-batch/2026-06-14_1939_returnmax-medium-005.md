### Observations (not task-blocking; no fix pushed)
- **Confirmation "State refund" card is labeled generically, not "California".** Prompt expects a "California refund summary card"; the card reads **"State refund $816"**. The CA association is only explicit on the Status page ("State return: CA"). Minor labeling gap.
- **Status timeline is hardcoded, not derived from `efile.status`.** `app/index/tto/file/status/_client.tsx:14-45` defines `steps` as a static constant (Return submitted=complete, Return received by IRS=current, rest pending); it ignores `efile.status`/`stateReturns` acceptance. So the page would show "submitted + received-current" even with no actual submission. Harmless for this task (post-transmit display is correct) but a latent correctness issue.
- **"Refresh status" is a coming-soon no-op** (`_client.tsx:87` → `showComingSoon`). The prompt doesn't require it (timeline already reads past Submitted), so not a blocker; flagged as the typical coming-soon stub pattern.
- **prep_work label drift:** prep_work names steps "Submitted, Accepted, Processing, Approved, Refund Sent"; the app uses "Return submitted, Return received by IRS, Return accepted, Refund approved, Refund sent". Cosmetic.
