## Bugs found

_One bullet per bug; keep `bug_count` in sync._

- **W-2 "on-site child care" answer is collected but never persisted (silent data loss).** The step `app/index/tto/income/w2/_step-child-care.tsx` holds the Yes/No answer in a throwaway `useState(null)`; it is never read from `formData` (so it can't be restored) and never written back via `updateField` on Continue (it just calls `goTo("savings")`). There is **no `onSiteChildCare` field** anywhere in the persistence chain (`W2FormData` in `_types.ts`, the `W2Form` entity in `types/tax-return-types.ts`, or the `fromW2Form`/`toW2Payload` mappers in `_helpers.tsx`). **Repro:** edit the Luma W-2, advance to the child-care question, pick **Yes**, finish (Done); re-open the same W-2 and return to the question → **both Yes and No are blank**, and `rm_tax_return.state.w2s[0]` has no child-care field. Every other W-2 box (1, 2, 10, etc.) persists; this one alone is dropped. Impact: the task's required modification cannot be saved or verified, and any downstream use of the Box 10 / dependent-care answer is impossible.
