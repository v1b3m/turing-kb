## Bugs found

_One bullet per bug; keep `bug_count` in sync._

- **An existing Documents Hub document cannot be re-tagged; "Edit details" only renames.** The kebab `Edit` opens `components/unified/vault/EditDocumentModal.tsx`, which exposes a **File name** field only — no tag selector — and `onSave` calls `renameDocument` exclusively. Tagging is wired solely in the upload flow's `TagFormStep` (`app/index/tto/.../add/upload/_client.tsx`), even though the store already provides `tagDocument(year,id,tag)` (`store/documents-store.ts`). Consequence: to change/assign a tag on a document already in the hub you must re-upload it, and **re-uploading silently creates a duplicate row** (`uploadMock` → `addDocument` with a fresh id; no filename dedupe). This blocks the task's "tag the existing receipt as Crypto Transactions" from producing the obvious intended end-state (one correctly-tagged doc). Suggested fix (mirrors medium-001's "store action exists but UI doesn't expose it"): add a tag `<select>` to EditDocumentModal and have `onSave` also call `tagDocument`. **Not yet implemented** — deferred to a fresh session (this session's context is large; see checkpoint).
