The Expert Review flow exists in full (`app/index/tto/expert-review/{,consent,check-summary,issues,tackle-issues,connect-expert,max}`). Its **actual structure is a single graph with two branches off Check Summary that both converge on `/consent → /max`** — not the prompt's linear sequence. The clean seed (0 issues) forces the short branch and makes the prompt's middle steps unreachable.

> [!note] Correction (2026-06-15, re-verified): an earlier version of this note called the two branches "mutually exclusive." That is wrong — they converge. The has-issues branch is `issues → connect-expert → tackle-issues ("Continue anyway") → consent → max`, so `/consent` is reached in **both** branches. The real defect is (a) consent is positioned *after* Check Summary instead of first, and (b) the complete seed yields 0 issues, so the entire issues→connect-expert leg (Fix + Chat) is bypassed. Verdict unchanged.

**Actual flow (verified live + source):**
- Entry "Start" (`entry-client.tsx:16-20`) runs `startCompleteCheck()` and `router.push("…/check-summary")` — it goes **straight to Check Summary, not to consent**. (Prompt expects consent Step 1/2 **before** Check Summary.)
- `seedCompleteCheckIssues()` (`store/tax-return-store.ts:198-284`) only flags **missing/invalid** data (no SSN, missing address, W-2 w/o EIN or wages≤0 or missing state row, 1099-INT/DIV w/o payer or amount≤0). The clean seed is **complete**, so it produces **0 issues**. Live: Check Summary shows **"Looking good! · 0 details for you to review."**
- Check Summary "Continue" (`check-summary/_client.tsx:23-29`) branches on `hasIssues`: **issues → `/issues`**, else **→ `/consent`**. With 0 issues it goes to **consent**. Verified live: landed on `/consent`.
- `/consent` (`_client.tsx:844-916`) renders **both** Step 1 (multi-use) and Step 2 (data sharing) as expandable cards, each "Review and sign" → signature drawer (full name + date + **Agree**). Once **bothDecided**, a single "Continue" → **`router.push("…/max")`** (`_client.tsx:896-906`). On the no-issues path this is the whole flow: **check-summary → consent → max**, and `/connect-expert` is never visited.
- `/connect-expert`'s only inbound link is `issues/_client.tsx:82` ("Review with a tax expert"; the Chat/Call options live on connect-expert), reachable **only on the has-issues branch**. So Chat (prompt step 6) is unreachable whenever there are 0 issues.
- The has-issues branch is **not** a dead end: connect-expert's "Continue" with no call/chat selected (`connect-expert/_client.tsx:103-107`) routes to `/tackle-issues` (if issues remain) or `/consent`; `/tackle-issues` "Continue anyway" (`tackle-issues/_client.tsx:13-16`) calls `bypassCompleteCheck()` then `/consent`. So **both branches converge on `/consent → /max`** — consent is reached either way, always *after* Check Summary, never before.

**Consequence:** the prompt's sequence — *Start → consent Step 1 → Step 2 → Check Summary → Issues (filter NEEDS REVIEW, Fix) → Connect Expert (Chat) → MAX (Get MAX)* — **cannot be performed in order on the clean seed**, for two reasons: (1) consent always comes *after* Check Summary, never first; and (2) the Issues list + Fix + Connect-Expert/Chat are all gated behind `hasIssues`, which is false for the complete seed. The only reachable path is **Check Summary → consent → max**, which omits 3 of the prompt's steps (issue count >0, Fix, Chat). (Consent and connect-expert are *not* mutually exclusive — the has-issues branch funnels through connect-expert into consent — but that branch is itself unreachable on the 0-issue clean seed.)

State-diff oracle: `startCompleteCheck()` writes `expertReview.completeCheck.issues = []` (0 issues) + sets `review` section in_progress; no other mutation observed on the traversed pages. State restored to seed.

**Verdict: bug-found (flow/seed mismatch, fix deferred).** Primarily a prompt/app mismatch: the prompt assumes a complete-check that surfaces issues and a single linear consent→issues→connect-expert→max flow, but the app (a) puts consent *after* Check Summary, and (b) finds 0 issues on the complete seed, so the Issues/Fix and Connect-Expert/Chat steps are bypassed entirely. No surgical fix — reconciling the flow order and seeding a complete-check issue so the Issues/Fix → Connect-Expert/Chat leg is reachable is flow-redesign/product-scope work (same disposition class as medium-011/014/023).
