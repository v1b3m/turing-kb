## Prep work

> Tax return for Maya Srinivasan (tax_return_id: 6aafcfc5) is in progress; current filing status is 'head_of_household'. The Filing Status page (/my-info/filing-status) shows five options: Single, Married Filing Jointly, Married Filing Separately, Head of Household, and Qualifying Surviving Spouse. The Filing Status Optimizer (/my-info/filing-status-optimizer) is triggered when a married status is selected and displays a side-by-side MFJ vs. MFS estimated refund comparison with a 'Recommended' highlight and a 'Use recommended status' button. The selected status is stored in filingStatus on the tax return store.

## Justification

A filer explores the filing status options and deliberately triggers the Filing Status Optimizer by selecting a married status, reviews the MFJ vs. MFS comparison, then reverts to Head of Household as the correct status and saves the final determination.

## Findings

_What happened, observations, state-diff result._

Tested on localhost:3001 from clean seed (`maritalStatus:"single"`, `filingStatus:"head_of_household"`).

- **`/index/tto/my-info/filing-status` is NOT a 5-option selector.** It's a read-only card that *derives* a single status from `personalInfo.maritalStatus`/`marriedFilingPlan`/`spousePassedYear` via `deriveFilingStatus()` (`_client.tsx:8-58`) and shows only that one status + explanation, with just Back/Continue. For the seed it shows **"Single"** (the fallback). There is no list of five options, no per-option descriptions, and **no control to switch to Married Filing Jointly**, so nothing can trigger the optimizer from here.
- **`deriveFilingStatus` can never return `head_of_household`** (no HoH branch — HoH is handled elsewhere, via the dependents/`other-filing-status` flow). So the page can neither display nor "save" HoH, and clicking **Continue** calls `setFilingStatus("single")`, which would *overwrite* the seed's `head_of_household` with `single`.
- **The Filing Status Optimizer exists and works — but is orphaned.** Direct nav to `/index/tto/my-info/filing-status-optimizer` shows exactly what the prompt expects: side-by-side **MFJ (Recommended, $3,240)** vs **MFS ($1,870)** estimated refunds, with bullet rationales and a **"Use recommended status"** button. But nothing in the UI links to it (grep-confirmed), and it's unreachable via the filing-status page.

**Net:** the prompt's flow is impossible — you cannot review five options/descriptions, cannot switch to MFJ to trigger the optimizer, and cannot save HoH on this page. The optimizer's own functionality (the MFJ-vs-MFS comparison + Recommended highlight) is correct when reached directly.
