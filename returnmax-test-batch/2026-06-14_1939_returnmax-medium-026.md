## Prompt

> Marcus needs to get his account set up before starting the 2025 return. Sign out of the current session to reach the auth pages. On the registration page (/auth/register), fill in first name 'Marcus', last name 'Reed', date of birth '04/17/1986', email 'marcus.reed@gmail.com', password 'Password123!', and password confirmation 'Password123!'. Submit the registration and confirm it passes email-uniqueness and Zod schema validation. If the system flags a conflict, navigate to the login page (/auth/login) instead, enter 'marcus.reed@gmail.com' and 'Password123!', and confirm routing to the Tax Home dashboard on success.

The prompt's auth routes and registration/login UI **do not exist**; only an email-only sign-in card exists.

1. **`/auth/register` → 404** (verified live, curl + browser). There is **no registration page** and **no registration form anywhere**. The sign-in card's only path to sign-up is **"Create an account," which is a `ComingSoonButton`** (`SignInCard.tsx:108-114`, `feature="Create an account"`) — i.e. an explicit coming-soon stub. No firstName/lastName/DOB/email/password/confirm fields, no Zod-schema UI, no email-uniqueness UI. (The store *has* `auth-store.register`, `users-store.addUser` (returns "User already exists" on dup email) and `isExistingUserEmail`, but **none are wired to any UI**.)
2. **`/auth/login` → 404** (verified live). There is **no password-based login**. The only auth UI is `SignInCard` at **`/signin`** (rendered via `HomeRouter → Content`), which has a **single email field, no password input** (`SignInCard.tsx:61-74`; confirmed live: `input[type=password]` absent). Its submit calls `signInWithEmail(email)` (`store/auth-store.ts:93`), which matches a user **by email only — password is never checked**.
3. **End state.** `handleSubmit` (`SignInCard.tsx:19-37`) routes to `ONBOARDING_PATH` if `!user.hasOnboarded`, else `UNIFIED_TAX_HOME_PATH`. Marcus (`users.json` `has_onboarded: false`; confirmed in the runtime `users` store — emails: hello@bluecedarstudio.co, **marcus.reed@gmail.com**, elena.petrova@…, sophia@…) would therefore route to **onboarding, not the Tax Home dashboard** the prompt expects.

**Consequence:** the prompt's flow — register with first/last/DOB/email/password/confirm + Zod + email-uniqueness, and on conflict fall back to `/auth/login` with email+password → Tax Home — **cannot be performed.** Both named routes 404; there is no registration form (coming-soon stub) and no password login (email-only). The only achievable action is email-only sign-in of an existing user at `/signin`, and for the prompt's un-onboarded Marcus that lands on onboarding, not Tax Home.
