2. **Itemized side already built & visible = $25,875.87.** The breakdown shows mortgage interest **$11,840.29** + property tax **$6,240.18** + SALT/charitable. ⚠️ **Stale prep_work / prompt:** the prompt says to *enter* the Rocket Mortgage interest ($11,840.29) and property tax ($6,240.18), but the **seed already contains them** (`deductions.mortgages[0]` interestPaid 11840.29, propertyTax 6240.18) and `deductionMethod` is already `"itemized"`. Same stale-seed pattern as medium-001/002. Nothing to enter.
3. **Recommendation = Itemized.** ✅ The "Itemized deductions $25,875.87" radio carries the **Recommended** badge (page computes `recommendedMethod = itemizedTotal > standardDeduction ? "itemized" : "standard"`).
4. **Selecting a method persists.** ✅ Clicking the radios flips `deductions.deductionMethod` immediately (`onSelectMethod → updateDeductions`); no separate Save (Continue advances to /other).

**The bug (refund pill does not update on method choice).** Federal refund pill = **$10,966** with Itemized selected. Clicking **Standard** → `deductionMethod` becomes `"standard"` in the store, radio checks, **but the pill stays $10,966**. Clicking back to **Itemized** → still **$10,966**. So the prompt's success criterion — "confirming the refund pill in the header updates after the choice is saved" — **cannot be observed**: the pill never changes between the two options.

Root cause: `lib/tax-engine.ts:283-286`
```
const deduction =
  state.deductions.deductionMethod === "itemized"
    ? itemizedDeduction
    : Math.max(standardDeduction, itemizedDeduction);  // "standard" path
```
When the user picks **standard** but itemized is higher, the engine still applies the **itemized** amount via `Math.max`. With itemized ($25,875.87) > standard ($22,500), both methods produce the *same* deduction → identical taxable income → identical refund. The "Standard deduction $22,500" radio is therefore **misleading** (selecting it does not apply $22,500), and the comparison page's pedagogical "see the difference" is undermined whenever itemized is the recommended option. (A true standard deduction would lower the deduction by $3,375.87 and visibly reduce the refund.)

State-diff oracle: clicking Standard then Itemized leaves `deductionMethod` back at the seed value `"itemized"`; no other state mutated; refund unchanged at $10,966 throughout.
