### Correction (2026-06-15 13:24) — #275 was the wrong fix; superseded by PR #281

The Maximizer was **not** actually unbuilt. A polished version (the curated 6-category scanner with the "350+ deductions" summary card, search box, and Claimed/Review rows — still visible on the `returnmax-ots-dev.vercel.app` deploy) had existed and was **deliberately removed** in commit `7f2b93a` *"remove maximizer page. #209"*. This note's test run happened **after** that removal, so it correctly saw a 404 — but concluded "build from scratch" without checking git history or the open issue. **Open issue [#209](https://github.com/turing-rlgym/returnmax/issues/209)** is the real ask: *"Deduction Maximizer 'Review' buttons are non-functional"* — expected = navigate to the deduction flow or show a Coming soon modal. The page was deleted as a stopgap, not retired.

PR #275 (from-scratch, data-driven, Review = surface-to-`selectedTaxBreakIds`) therefore diverged from the established design and from #209's expected behavior. **Corrected in PR https://github.com/turing-rlgym/returnmax/pull/281**: restores the original `_client.tsx`/`page.tsx`, fixes schema drift (`studentLoan` → `studentLoans`), and makes the Review buttons functional per #209 — routable items navigate to their deduction flow; non-routable items (e.g. *Home office deduction*) open the shared **`UnifiedComingSoonModal`** via `useComingSoonAction()`. Live-verified (chrome-cdp `turing`, localhost:3000): page renders, routable Review navigates (*American Opportunity Credit* → `/index/tto/deductions/education-credits`), non-routable Review shows "Home office deduction is coming soon." `pnpm typecheck` + `eslint` + `prettier` clean. **status → fix-pushed** (PR #281 pending merge; closes #209).
