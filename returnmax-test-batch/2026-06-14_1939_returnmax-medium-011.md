## Prompt

> Notification settings are a mess after switching devices. In Notifications settings (/my-info/notifications), turn on SMS notifications (currently off) and turn off marketing emails (currently on). Then in the main Settings store, toggle the progress bar visibility off, set the auto-save interval to 60 seconds (from the current 30-second default), and enable high contrast mode. Once all five changes are saved, open the Notification Bell in the header to mark all unread notifications as read.

preferences/settings the app does not implement. The prep_work invents a settings model
(`settings_id b5635a79` with `sms_notifications`, `marketing_emails`, `accessibility_high_contrast`,
and a "main Settings store" UI) that has no counterpart in the codebase.

Verified against source + live app:

1. **"turn on SMS notifications (currently off)"** — ✗ no single SMS toggle exists. `/my-info/notifications`
   (`app/index/tto/my-info/notifications/_client.tsx`) has **3 granular text opt-ins** bound to
   `personalInfo.textNotifications` (`criticalAlerts`, `importantDates`, `offersAndTips`). Seed =
   `{criticalAlerts:true, importantDates:true, offersAndTips:false}` → already mostly **on**, not off.
2. **"turn off marketing emails (currently on)"** — ✗ **no email/marketing-email control anywhere**.
   The notifications page is SMS-only. The nearest concept (`offersAndTips`) is OFF, not on.
3. **"toggle the progress bar visibility off"** — ✗ no UI. `showProgressBar` exists in the Settings
   store (`store/settings-store.ts`, seed `true`) but the only consumers are `components/app/ProgressBar.tsx`
   (read) and `StoreInitializer`. There is **no settings page** to mutate it (`grep useSettingsStore` → 2 read-only hits).
4. **"set auto-save interval to 60s (from 30s default)"** — ✗ no UI. `autoSaveIntervalMs` (seed `30000`)
   is in the store but never editable.
5. **"enable high contrast mode"** — ✗ **does not exist** (`grep highContrast|high contrast` → 0 hits;
   `SettingsState = {autoSave, autoSaveIntervalMs, showProgressBar}` only).
6. **"mark all unread notifications as read" via the header bell** — ✅ **works**. Bell (aria-label
   "Notifications") opens the tray; "Mark all as read" (`NotificationTray` → `markAllRead`) flips both
   unread items. State-diff oracle: `rm_notifications` unread **2 → 0**; nothing else mutated. State restored to seed.

**Verdict: bug-found (app gap, fix deferred).** This is primarily a **prompt/app mismatch** — the prompt
references a preferences model the app doesn't have. The genuine app-side observation is that the Settings
store persists `showProgressBar`/`autoSaveIntervalMs` with **no UI to edit them** (dead settings), and the
documented preferences (SMS master toggle, marketing emails, high-contrast theme) are unimplemented.
No surgical fix exists — building a Settings UI + accessibility theme + email-pref model is a feature
build, same class as medium-010 (EIC stub) and medium-004 (deduction semantics). Flagged, not implemented.
