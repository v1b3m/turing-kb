## Resolution — 2026-06-15 (PR #257, branch `chore/keep-hacking`)

Reproduced and fixed against the `returnmax` worktree (chore/keep-hacking), served on **localhost:3000** (IPv6). Note: the worktree↔port mapping changed since [[returnmax-test-batch-workflow]] was written — `returnmax-1`/3001 is now on `ots_dev`, behind us.

**Root cause (Issues 1 & 4 date):** `components/ui/DateInput.tsx` emits ISO (`YYYY-MM-DD`), but the charitable items/stock step ran `normalizeUsDateString` (assumes `mm/dd/yyyy` digit order) on it → `2025-02-02` became `20/25/0202`. This made valid dates fail validation, and the mangled value was persisted (the reported `20/25/0503` = ISO `2025-05-03` reordered).

- **Issue 1A** (valid date rejected) — FIXED. `validateCharitableDonationDate` now validates the ISO value; removed the `normalizeUsDateString` calls in `charitable-wizard-steps.tsx`. Verified: `02/02/2025` advances, stored as `2025-02-02`.
- **Issue 1B** (saved despite error) — FIXED. `getCategoryPayload` gates `dateContributed` on validation; invalid → `""`. Verified: `02/02/2024` blocks ("must be in 2025"), store keeps `""`.
- **Issue 2** (charitable missing from Deductions & Credits) — NOT REPRODUCIBLE. `charitable` is already in the overview catalog under the "Charitable Donations" group (browse + active list). No change.
- **Issue 3** (search misses Medical, etc.) — FIXED. Global search used a hand-maintained list that drifted from the real topics. Extracted `overviewTopics` to a dependency-free module (`lib/deductions-overview-topics.ts`) and derived the search index's deduction/credit entries from it. Verified: "medical", "health savings", "roth ira", "adoption" all resolve.
- **Issue 4** (date `20/25/0503`) — FIXED (same root as Issue 1). The amount-vs-`fairMarketValue` split is **by design**: cash → `amount`, non-cash items/stock → `fairMarketValue`.

`tsc --noEmit` and `eslint` clean. No test suite in repo.
