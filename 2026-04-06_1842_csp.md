# ServiceNow Customer Service Portal (CSP) — Overview

## What It Is

The **Customer Service Portal (CSP)** is a self-service web portal within ServiceNow's **Customer Service Management (CSM)** product. It provides an external-facing interface where customers can manage their interactions with an organization — creating and tracking cases, browsing knowledge articles, chatting with agents, and handling account details — without needing direct access to the ServiceNow backend.

CSP is built on ServiceNow's **Service Portal** framework (portal designer, widgets, pages, themes) and ships as a pre-configured portal with CSM-specific pages and widgets out of the box.

---

## Key Capabilities

### Case Management
- Create product cases and cases for install base items
- View, modify, and close existing cases
- Track case status and history
- Complete customer satisfaction (CSAT) surveys after resolution

### Self-Service & Deflection
- Search the **knowledge base** for answers before creating a case
- Search the **customer service community** for peer answers
- AI-powered suggestions to deflect cases with relevant content

### Live & Virtual Agent Support
- **Live chat** with customer service agents
- **Virtual Agent** conversations for guided, automated assistance
- Engagement Messenger for embedded messaging experiences

### Account & Contact Management
- Self-register for portal access
- Manage contacts and customer registration requests
- Assign contacts to assets
- Update contact information
- Change password
- Manage notification preferences

### Catalog & Requests
- Request items or services from the service catalog
- Approve requests
- View request status

### Asset & Install Base
- View asset and product information
- View install base items
- Create cases directly for install base items

### Localization
- Language selection for guest (unauthenticated) users
- Multi-language support

## Architecture

CSP sits on top of the **Service Portal** framework:

```
┌──────────────────────────────────────────┐
│           Customer Service Portal        │
│  (pre-built portal with CSM widgets)     │
├──────────────────────────────────────────┤
│         Service Portal Framework         │
│  Pages · Widgets · Themes · Layouts      │
├──────────────────────────────────────────┤
│        ServiceNow Platform (NOW)         │
│  CSM Tables · ACLs · Business Rules      │
└──────────────────────────────────────────┘
```

### Core building blocks

| Concept       | Description                                                                                  |
| ------------- | -------------------------------------------------------------------------------------------- |
| **Portal**    | A named entry point (`/csp`) with its own theme, pages, and access rules                     |
| **Pages**     | URL-addressable views composed of containers, rows, columns, and widgets                     |
| **Widgets**   | Reusable Angular components with server script, client script, HTML template, CSS, and options |
| **Themes**    | CSS/SCSS + header/footer widgets that control portal look-and-feel                           |
| **Instances** | A widget placed on a page with its own configuration (stored in `sp_instance`)               |

### Widget anatomy

Each widget has:
- **HTML Template** — Angular-flavored markup
- **Client Script** — client-side controller (`function() { var c = this; ... }`)
- **Server Script** — GlideRecord / server-side logic (`(function() { ... })();`)
- **CSS/SCSS** — scoped styles
- **Options** — JSON-configurable instance options (passed via `c.options` / `data`)

Options can be provided inline in HTML or generated server-side:

```html
<widget id="widget-cool-clock"
        options='{"zone":"America/Los_Angeles","title":"San Diego"}'>
</widget>
```

## Configuration & Setup

### Activation
CSP is delivered via CSM plugins. Activating the **Customer Service Management** plugin (`com.sn_customerservice`) provisions the portal, pages, widgets, and demo data.

### Branding & Theming
- Customize the portal theme (colors, logo, fonts) via the **Branding Editor** or by editing the theme record directly
- Modify header/footer widgets for navigation links and layout
- Custom CSS variables control navbar, user profile visibility, and responsive breakpoints

### Portal Properties
Key portal record fields:
- **URL suffix** — the path segment (e.g., `csp`)
- **Theme** — reference to the theme record
- **Login page / Authentication** — can be enabled or disabled
- **Default language** — controls guest user locale

### Widget Customization
- Clone and modify out-of-box widgets (never edit OOB directly)
- Use the **Widget Editor** (Service Portal > Widget Editor) for live preview
- Pass options via the **Additional Options** JSON field on `sp_instance`

## CSM vs. CSP — Clarification

- **CSM (Customer Service Management)** is the full product: agent workspace, case management, routing, SLAs, playbooks, field service integration, etc.
- **CSP (Customer Service Portal)** is the *customer-facing portal* within CSM — the self-service front door.

CSM also includes the **Agent Workspace** (internal-facing) and **Configurable Workspace** for agents, which is separate from CSP.
