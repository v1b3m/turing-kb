# Git tags — lookout-desktop release flow

For releasing `turing-rlgym/lookout-desktop`. The release workflow
attaches build binaries to the GitHub release page for any tag starting
with `v` (see `.github/workflows/release.yml`).

## Create a tag

Lightweight — just a pointer to a commit:

```sh
git tag v1.0.0
```

Annotated — recommended for releases (stores tagger, date, message):

```sh
git tag -a v1.0.0 -m "Release 1.0.0"
```

Tag a specific commit (not `HEAD`):

```sh
git tag v1.0.0 abc1234
```

## Push a tag

`git push` does **not** push tags by default. Push explicitly:

```sh
git push origin v1.0.0
```

Or push every local tag at once:

```sh
git push origin --tags
```

## Naming

- Must start with `v` — the release workflow filter is
  `startsWith(head_branch, 'v')`.
- Standard semver: `v1.2.3`, `v2.0.0`.
- Pre-release / first-test: `v0.0.1-test`, `v1.0.0-rc.1` — disposable
  while iterating.

## What happens after `git push origin <tag>`

1. GitHub auto-creates the release page with `Source code (zip)` and
   `Source code (tar.gz)` immediately (those are GitHub's, not ours).
2. `package.yml` + `trainer-installers.yml` build the binaries in
   parallel (~3–10 min).
3. `release.yml` attaches them to the release via
   `softprops/action-gh-release@v2`.

Total wall-clock: ~5–10 min. Refresh the release page; binaries appear
incrementally as each upstream workflow finishes.

## Sanity-check before pushing

```sh
git rev-parse HEAD              # confirm HEAD is what you intend to tag
git tag -l 'v*'                 # list v-prefixed tags locally
git ls-remote --tags origin     # list tags already on remote
```

## Delete a tag (mistakes)

```sh
git tag -d v1.0.0                       # delete local
git push origin --delete v1.0.0         # delete remote + drop the release
```

If the release was already published, you may also need to delete it from
the GitHub Releases UI — it can linger as an empty page after the tag
is removed.
