### 2. hard-039 — Blank medical expense row on Continue

**Verdict: Root cause #1 FIXED, Root cause #2 UNFIXED**

**Root cause #1 (FIXED):** `emptyMedicalExpenses()` in `lib/medical-expenses.ts` no longer seeds a blank placeholder row — `otherExpenses` now defaults to `[]`. `normalizeMedicalExpenses()` also filters out blank entries. Fixed in commit `444ff2f`.

**Root cause #2 (UNFIXED):** `mergeOnboardingTaxBreakIds()` in `lib/deductions-onboarding.ts` unconditionally adds `"medical"` to `selectedTaxBreakIds` regardless of what the user answered during the FindTaxBreaksWorkflow. This means medical appears as an active deduction topic even when the user said "No" to it.

### 3. hard-021 — personal_info status flips to "not_started"

**Verdict: FIXED**

`RouteStatusSync` in `components/app/RouteStatusSync.tsx` had a bug where the useEffect cleanup unconditionally reset any `in_progress` section to `not_started`. Fixed in commit `7fc8a5e` with two guards: (1) `section !== nextSection` prevents reset on same-section navigation, (2) `didSetToInProgressRef.current` prevents reset when another component was the one that promoted the status.

### 4. hard-022 — State return changes not in state_returns.json

**Verdict: FIXED (with seed data caveat)**

Summary fields (`stateAdjustments`, `stateDeductions`, `stateCredits`, `stateRefundOrOwed`) were never recomputed after detail fields changed. Fixed in commit `bef1ac4` by adding `computeStateReturnSummary()` in `lib/compute-state-return-summary.ts`, wired into all four state flow pages (income, adjustments, credits, complete).

**Caveat:** Seed data in `defaultState.json` has summary values inconsistent with its own detail fields. When the fix recomputes from detail, the values differ from the seed, which could cause false gym verification failures. The seed should be regenerated.

### 5. hard-017 — Donation clearing + 1099-INT empty rows

**Verdict: Issue 1 NOT REPRODUCIBLE in code, Issue 2 CONFIRMED BUG**

**Issue 1 (likely fixed):** The charitable wizard (`use-charitable-flow.ts`) correctly preserves `description` and `dateContributed` when editing. `openEditGroup()` populates form data from stored contributions via `contributionToFormData()`. `getCategoryPayload("cash")` always includes `description` and `dateContributed` from form data. `handleCharityStartContinue` preserves all fields when `editingIdRef.current` is set. No path was found that would clear these fields when only the amount is changed.

**Issue 2 (CONFIRMED):** `initialIntForm` in `app/index/tto/income/1099-int/_client.tsx` (line 231-234) defaults to 2 empty `stateRows` entries. `buildFormPayload` (line 756) passes them through unfiltered: `stateRows: form.stateRows`. These empty rows are stored with every new 1099-INT.

**Fix needed:** Filter out empty stateRows before saving, or default to `[]`.
