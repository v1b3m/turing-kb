# YouTube Data API Catalog Import Report

Date: 2026-04-30

## Executive summary

The YouTube Data API can be used to collect catalog data for this app: videos, channels, playlists, playlist items, comments, and thumbnail URLs. It is a good fit for generating a `pg/data` import cache and then normalizing that cache into app-compatible JSON.

Recommended import shape:

```text
pg/data/
  raw/
    videos.res.json
    channels.res.json
    playlists.res.json
    playlist-items.res.json
    comments.res.json
    search.res.json
  videos.json
  channels.json
  playlists.json
  playlist_videos.json
  comments.json
  import-manifest.json
```

Use thumbnail URLs from the API response instead of downloading thumbnail image files by default. Downloading and committing real YouTube thumbnail binaries is higher risk than storing API-provided URLs and cache metadata.

The main policy constraint is that YouTube API data should be treated as cached API data, not permanent fixture data. YouTube's developer policies allow limited temporary storage of API data, but cached API data generally must be deleted or refreshed within 30 calendar days and kept consistent with current YouTube data.

Source: https://developers.google.com/youtube/terms/developer-policies

## Can we dump 2,000 videos?

Yes, technically.

Efficient path:

```text
Discover video IDs
-> hydrate videos in batches with videos.list
-> collect channel IDs from video snippets
-> hydrate channels in batches with channels.list
-> optionally hydrate playlists and playlist items
-> write raw API responses and normalized app JSON
```

Known-ID hydration is cheap. `videos.list` accepts multiple IDs per request, so 2,000 videos can be hydrated in roughly 40 calls if each call carries 50 IDs.

The expensive part is discovery:

- `search.list` costs 100 quota units per request.
- Each additional search page costs another 100 units.
- Channel uploads discovery via `playlistItems.list` is cheaper at 1 unit per request, once you know channel IDs.

A practical collection plan:

1. Seed a list of channels or search queries.
2. Use `search.list` sparingly to discover channel/video/playlist IDs.
3. Use `channels.list(part=contentDetails)` to get each channel's uploads playlist.
4. Use `playlistItems.list` to page through uploads.
5. Use `videos.list` to hydrate full video metadata in 50-ID batches.
6. Write raw responses to `pg/data/raw/*.res.json`.
7. Write normalized rows to `pg/data/*.json`.
8. Include `fetchedAt`, `expiresAt`, `source`, and source IDs.

## Endpoint fit

### `videos.list`

Best use: hydrate known video IDs.

Good for:

- title
- description
- thumbnails
- channel ID/title
- published date
- category ID
- tags
- duration
- view count
- like count
- comment count
- caption/definition flags
- embed eligibility

Gaps:

- no public dislike count
- category requires ID-to-label mapping
- some stats may be absent for restricted videos

Source: https://developers.google.com/youtube/v3/docs/videos/list

### `channels.list`

Best use: hydrate channel records and discover upload playlists.

Good for:

- channel title/name
- description
- custom URL / handle fallback
- avatar thumbnails
- banner image
- subscriber count
- video count
- total view count
- uploads playlist ID

Gaps:

- no clean verified-badge field
- subscriber count can be hidden or rounded

Source: https://developers.google.com/youtube/v3/docs/channels/list

### `playlistItems.list`

Best use: fetch videos inside a known playlist, including channel uploads playlists.

Good for:

- playlist ID
- video ID
- item position
- provisional title/description/thumbnail
- video publish timestamp

Notes:

- Use this for discovery, then hydrate returned `videoId`s with `videos.list`.

Source: https://developers.google.com/youtube/v3/docs/playlistItems/list

### `playlists.list`

Best use: hydrate public playlist metadata.

Good for:

- playlist title
- description
- thumbnails
- channel owner
- item count
- privacy/status where available

Source: https://developers.google.com/youtube/v3/docs/playlists/list

### `search.list`

Best use: sparse discovery of video/channel/playlist IDs.

Good for:

- finding initial video IDs
- finding initial channel IDs
- finding public playlists

Constraint:

- `search.list` costs 100 quota units per request, so use it sparingly and cache results.

Source: https://developers.google.com/youtube/v3/docs/search/list

### `commentThreads.list` and `comments.list`

Best use: collect public comments for imported videos.

Good for:

- top-level comments
- reply counts
- returned replies
- author display metadata
- text
- like count
- publish/update timestamps

Source:

- https://developers.google.com/youtube/v3/docs/commentThreads/list
- https://developers.google.com/youtube/v3/docs/comments/list

### Thumbnail data

Best use: store API-provided thumbnail URLs.

The API returns thumbnail URLs inside resource `snippet.thumbnails`, typically with sizes like:

- `default`
- `medium`
- `high`
- `standard`
- `maxres`

Preferred selector:

```text
maxres.url
|| standard.url
|| high.url
|| medium.url
|| default.url
```

Do not call `thumbnails.set` for imports. That endpoint uploads or replaces a video thumbnail and requires OAuth.

Source: https://developers.google.com/youtube/v3/docs/thumbnails

## Quota impact

Default quota is 10,000 units per day. Every request costs at least 1 unit, including invalid requests. Additional pages cost again.

Relevant costs:

| Method | Cost |
|---|---:|
| `videos.list` | 1 |
| `channels.list` | 1 |
| `playlistItems.list` | 1 |
| `playlists.list` | 1 |
| `commentThreads.list` | 1 |
| `comments.list` | 1 |
| `search.list` | 100 |
| `thumbnails.set` | 50 |
| `videos.insert` | 1600 |

Practical estimate for a 2,000-video import:

- Hydrate 2,000 known videos: about 40 quota units using `videos.list` batches of 50.
- Hydrate 200 channels: about 4 quota units using `channels.list` batches of 50.
- Fetch 2,000 upload playlist items: about 40 quota units if using `playlistItems.list` pages of 50.
- Search discovery: 100 units per page, so this dominates cost if overused.

Source: https://developers.google.com/youtube/v3/determine_quota_cost

## Policy and legality notes

This is not legal advice. From an engineering/compliance perspective, a temporary `pg/data` cache is much safer than committing permanent YouTube-derived fixture data.

The key policy points:

- YouTube API data should be treated as API data from YouTube, not owned fixture data.
- Cached API data is generally limited to temporary storage.
- Cached API data should be deleted or refreshed within 30 calendar days.
- Stored data should stay consistent with current YouTube data.
- Do not scrape YouTube pages to build the dump; use the documented API.
- Do not expose the dump as a separate data product or redistribution service.
- Store thumbnail URLs by default; downloading and committing thumbnail binaries is higher risk.
- Keep attribution/source metadata so imported rows can be audited and refreshed.

Best practical approach:

- Keep `pg/data` ignored or temporary.
- Include `fetchedAt` and `expiresAt` in every normalized row or in a manifest.
- Add a refresh/delete script before using the data in demos or generated fixtures.
- If permanent seed data is needed, use generated/synthetic data or content we own/license.

Source: https://developers.google.com/youtube/terms/developer-policies

## Recommended importer plan

Add a script such as:

```text
scripts/import-youtube-catalog.mjs
```

Inputs:

```text
YOUTUBE_API_KEY
--seed-query "nextjs tutorial"
--seed-channel UCuAXFkgsw1L7xaCfnd5JJOw
--target-videos 2000
--out pg/data
```

Pipeline:

1. Load seed queries and seed channel IDs.
2. Use limited `search.list` calls to discover channels, playlists, and videos.
3. Use `channels.list` to get channel metadata and uploads playlist IDs.
4. Use `playlistItems.list` to collect video IDs from uploads and public playlists.
5. De-duplicate video IDs.
6. Use `videos.list` in 50-ID batches to hydrate complete video metadata.
7. Use `channels.list` in 50-ID batches for all referenced channel IDs.
8. Optionally use `commentThreads.list` for a small bounded number of comments per video.
9. Save raw API responses under `pg/data/raw/*.res.json`.
10. Save normalized app-shaped JSON under `pg/data/*.json`.
11. Write `pg/data/import-manifest.json` with quota estimate, source, `fetchedAt`, and `expiresAt`.

Do not put the API key in generated files.

## Bottom line

Yes, it is technically possible to dump similar catalog data into `pg/data`, including 2,000 videos, channels, playlists, playlist memberships, comments, and thumbnail URLs. The safer implementation is a temporary, refreshable API cache with normalized JSON, not a permanent checked-in copy of YouTube API data or downloaded thumbnail assets.
