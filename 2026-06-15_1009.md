## Triage & resolution (2026-06-15)

### Issue 1 — REAL BUG, fixed

Root cause: the deductions UI fully supports multiple 1098-E entries ("Add another 1098-E", per-row
edit/delete, summary total), but the store held `deductions.studentLoan` as a **single**
`StudentLoan1098E | null` object. With more than one loan, `entriesToStoreValue` collapsed them — joining
lender names with `"; "` and **summing** `interestPaid` — producing exactly the reported
`Nelnet; testing lender` / `3873.45`. Every sibling multi-entry deduction (`mortgages`,
`charitableContributions`, `carLoanInterest`) is already an array; `studentLoan` was the lone anomaly.

Fix: store `deductions.studentLoans` as an **array** of records (each with its own `id`), mirroring
`carLoanInterest`. Persist each entry directly — no merging. Tax engine sums interest across loans before the
$2,500 cap. Persist version bumped 39→40 with a migration lifting the legacy single object into a
one-element array; seed default state updated to the new shape.

Verified live (turing profile, localhost:3000): edited Nelnet→540.45 and added `testing lender`/3333 →
`studentLoans` now holds **two separate records**, not one merged record; survives reload; legacy v39
object-shaped state migrates cleanly to the array.

Commits: `2b6859d`, `3d9f8fe`, `ab73ac4` (branch `chore/keep-hacking`).
PR: https://github.com/turing-rlgym/returnmax/pull/260 (→ `ots_dev`).

### Issue 2 — NOT a bug

`energyImprovementAnswers` (all-null) is part of the **initial seed**
(`data/initializers/initialize-tax-return.ts` → `emptyEnergyImprovementAnswers()`, byte-for-byte the object
quoted). The reporter's own criterion ("if expected, it should already exist in the initial JSON") is
satisfied — it is the factory default, not a newly created record. No change.

### Issue 3 — NOT a bug

The extra fields (`netUnrealizedAppreciation`, `firstYearOfRoth`, `stateTaxWithheld`, `stateId`,
`stateDistribution`, `localTaxWithheld`, `localityName`, `localDistribution`) are **required fields of the
`Form1099R` interface** with sensible defaults (`0` / `""`). They are real 1099-R boxes (state/local
withholding, net unrealized appreciation, first year of Roth) the form UI doesn't surface yet, so each saved
record carries the full shape. By design. No change.
